# Security

PokéBench runs LLM agents with tool access in a loop, which makes it a small but real
agentic system. Controls below are mapped to **OWASP Top 10:2025** and the
**OWASP Top 10 for LLM Applications**, with implementation status per milestone.

| Control | Threat addressed | Status |
|---|---|---|
| **Emulator + agent sandboxing.** Game + agent run in Docker with no network egress except an allowlisted LLM-API proxy. The environment the agent acts on can never become a leg of the "lethal trifecta" (private data + untrusted content + exfiltration channel). | LLM06 Excessive Agency; Rule-of-Two | **Egress control built and verified 2026-08-11; still opt-in and still never used for a real agent run.** `docker-compose.yml` + `docker/proxy/` (tinyproxy default-deny allowlist → `api.anthropic.com`); agent container attached only to the `sandbox` network (`internal: true`, no gateway), proxy bridges `sandbox` to `egress`. Applies **only** when you launch via `docker compose run …`; a direct `pokebench run` bypasses it entirely — every run so far has, including the whole M3 sweep. **Verified 2026-08-11** (Docker Engine 29.6.2, Compose v5.3.1 — `docker compose build` then `up`, both images built clean): from inside the sandboxed `agent` container, an unauthenticated HTTPS request to `api.anthropic.com` (no key sent, no billing) reached the real endpoint through the proxy and got a genuine `401 {"type":"authentication_error","message":"x-api-key header is required"}` — the **allow path**. A request to `example.com`, and separately to `api.openai.com`/`generativelanguage.googleapis.com`, was refused with `403 Filtered` at the proxy, corroborated server-side in the tinyproxy log (`Proxying refused on filtered domain "example.com"` vs `Established connection to host "api.anthropic.com"`) — the **deny path**, and confirmation the documented gap below (OpenAI/Google not yet allowlisted) actually holds. A raw-socket connection attempt straight to `1.1.1.1:443` and `8.8.8.8:53`, bypassing the proxy's `HTTPS_PROXY` env var entirely, failed with `OSError: Network is unreachable` — `docker network inspect` confirms the `sandbox` network has no gateway (`"Internal": true`), so **the control is enforced at the network layer, not merely advisory**: an agent process that ignored `HTTPS_PROXY` would get no route out, not a policy decision it could evade. **Still not verified:** no `pokebench run`/`bench`/`replay` has ever executed inside the container — only manual network probes via `--entrypoint sh` (`docker/README.md` has the exact commands). The app's own HTTP client (`agents/_http.py`, `httpx.Client()`, `trust_env=True` by default) was confirmed to inherit `HTTPS_PROXY`/`HTTP_PROXY` from the container environment, but an actual API call through it was not exercised end-to-end. **M3 widened the gap:** the allowlist still names Anthropic alone (both `api.openai.com` and Google's endpoint were confirmed blocked above), so they must be added before those legs could be sandboxed — and the local Ollama leg needs `host.docker.internal:11434`, i.e. a *host route*, which is a different hole in an `internal: true` network than an egress allowance and may not be worth punching. |
| **Unbounded-consumption guards.** Hard per-run step, token, and dollar caps enforced *by the runner code*, never by the prompt. Caps are declared per scenario (`scenarios/*.yaml`). | LLM10 Unbounded Consumption | **Active.** Declared in the scenario spec (M0), enforced in `runner/loop.py` (M2). M3 added CLI overrides (`--max-turns/--max-usd/--max-tokens/--max-minutes`) so a turn-matched sweep can lift the other caps to pure kill-switches; overrides are still runner-enforced, never prompt-enforced. **One found side effect (2026-08-14):** the shared per-turn `max_output_tokens=1024` answer cap is also, for Anthropic only, the extended-thinking budget (Anthropic bills thinking against the same `max_tokens` field; the other three vendors' adapters send no comparable per-call reasoning-budget parameter). A guard against runaway output silently became a deliberation cap for one vendor. `ModelConfig.thinking_budget_tokens` (opt-in via `--thinking-budget` on `bench`/`sweep`) gives Anthropic an explicit, separate thinking budget instead; unset (the default, and every published row) leaves this control exactly as before. See `HANDOFF.md`'s 2026-08-14 entry for the calibration data. |
| **Secrets hygiene.** API keys via environment variables only; nothing key-shaped in the repo; gitleaks runs in pre-commit. Keys travel in headers, never in a URL. | A04:2025 (Cryptographic/secret failures); LLM02 | Configured, not enforced — `.pre-commit-config.yaml` pins gitleaks v8.24.3, but it only runs for a developer who has run `pre-commit install`, and CI runs `ruff` + `pytest` only, so **nothing gates gitleaks on push**. Stated plainly because "configured" and "enforced" are exactly the distinction this file exists to keep honest. **M3 fixed a real leak:** Gemini's `?key=` query parameter printed a live API key into an httpx traceback. The key now rides an `x-goog-api-key` header, `agents/_http.py` redacts query strings in `ProviderHTTPError`, and a regression test asserts no key ever appears in a URL. **Rotation was assessed and judged unnecessary**, not skipped: a search of the full git history and working tree for key-shaped strings (`AIza…`, `sk-…`, `sk-ant-…`, PEM blocks) found zero hits — the exposure was to local logs and console output only, nothing key-shaped ever reached the repository. The fix above (`redact()` truncating the URL at `?`) is what stops recurrence, and `.pre-commit-config.yaml` already gates future commits with gitleaks. |
| **Supply chain.** `uv.lock` pins the full dependency tree; CI installs `--frozen`; no install scripts; dependency review on updates. | A03:2025 Software Supply Chain Failures | Active (M0) — lockfile + CI |
| **Audit log.** Every run emits a JSONL trace: one record per action with the action and resulting game state (plus screenshots). The benchmark's replay artifact doubles as a complete tool-call audit trail. | LLM audit/traceability | Active (M0) — `harness/trace.py`; extended with model I/O in M1 |
| **No ROM distribution.** The repo ships no copyrighted material; ROM presence is user-supplied and hash-verified locally with a warning-only check. | Legal / provenance | Active (M0) |
